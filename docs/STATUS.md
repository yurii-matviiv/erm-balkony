# Стан проєкту

> Частина документації ERM. Індекс і навігація: [CLAUDE.md](../CLAUDE.md). Читай цей файл, лише якщо задача стосується теми вище.

## Стан проєкту (станом на останнє оновлення)

Зроблено:
- Users, Clients, Suppliers (+contacts, +payment profiles) — повний CRUD, синхронізовано.
- Vacancy / Candidate / VacancyApplication + сторінка "Воронка вакансій" — CRUD готовий, синхронізовано 194+44 кандидати з двох старих форм.
- Lead / LeadServiceType + базова форма заявки (без сторінки воронки і без синхронізації історичних лідів) — щойно додано.
- Сторінка "Синхронізація зі старої БД" — універсальний UI для всіх маперів вище.
- `InvoiceAnalytics` — сторінка аналітики рахунків (KPI-індикатори, фільтр дат, таблиця надходжень з ПриватБанк-перевіркою, таблиця витрат по групах). Нова таблиця `expenses` для загальних витрат.
- Модуль "Взаєморозрахунки" (`settlements`) — інкасації/перекази між компанією та власниками, обчислюваний баланс, індикатори, аудит — див. окремий розділ.

Не зроблено / відомі прогалини:
- `SupplierPaymentProfile` — таблиця порожня, платіжні дані в старій системі лежали як вільний текст у коментарях (знайдено IBAN у нотатках кількох постачальників) — перенесення вручну, не автоматизовано.
- Власні юридичні особи/ФОПи компанії для рахунків клієнтам — лише обговорено, не реалізовано.
- BankIntegration / relation manager на `UserResource` для менеджерів — узгоджено архітектурно ("так, погоджуюсь"), не реалізовано.
- 9 старих "клієнтів"-постачальників без розпізнаваної назви компанії (напр. "Тетяна Галіон", "будівна компанія") — залишені в `clients` як є, не перенесені.
- Вакансія "Замірник", яку згадував користувач — **відсутня в історичних даних обох старих форм** (`candidates.job_vacancy` і `add_candidate.position_candidate` мають лише installer/assistant/manager); якщо потрібна — додати вручну, без історії.
- Розширені поля кандидата зі старої `candidates` (досвід роботи, навички, оцінки за результатами розмови тощо) — не перенесені, MVP свідомо обмежений базовими полями.
