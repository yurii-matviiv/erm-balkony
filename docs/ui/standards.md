# Стандарти адмінки: елементи Filament і єдиний вигляд

> Частина документації ERM. Індекс: [CLAUDE.md](../../CLAUDE.md). **Читати ПЕРЕД створенням або зміною будь-якої сторінки/блока адмінки.**

## 1. Головне правило

Адмінка будується зі **стандартних елементів Filament**. Власна розмітка (`<table>`, самописні кнопки, inline-стилі, свої вкладки) — **лише коли потрібного елемента в Filament немає**, і з коментарем у коді, чого саме не вистачило. Якщо такий елемент знадобився двічі — він стає **проєктним стандартом**: робиться один раз глобально (компонент/стиль), описується в розділі 4 нижче, і далі використовується всюди однаково.

Мета: сторінки виглядають однаково, елементи стоять на тих самих місцях і не «стрибають» від сторінки до сторінки.

## 2. Що брати для чого

| Потрібно | Беремо (Filament) | Приклад у проєкті |
|---|---|---|
| Таблиця зі своїх даних (Eloquent) | `Table` + `TextColumn`, `->striped()`, `->paginated([...])`, `recordActions` | `Reminders`, `ListLeads` |
| Таблиця з масиву/сервісу, не з моделі | `Table` + `->records(fn () => ...)` (пошук, сортування — у замиканні) | `Marketing\SeoPositions` |
| Вкладки | `<x-filament::tabs>` + `<x-filament::tabs.item>` (вигляд — глобальний, розділ 4.1) | `Reminders`, `SeoPositions` |
| Кнопки дій на сторінці | `Action` у `getHeaderActions()` | `SeoPositions`, `Reminders` |
| Підтвердження небезпечної/зовнішньої дії | `->requiresConfirmation()` | кнопки знімка SEO |
| Повідомлення про результат | `Filament\Notifications\Notification` (success/warning/danger) | `SeoPositions` |
| Повноекранна довідка блока | `HasInstructionModal` → кнопка «Інструкція» ([INSTRUCTIONS.md](../INSTRUCTIONS.md)) | `ManagerConversion` |
| Статуси в таблиці | `TextColumn::badge()->color()`; кольори лише `success`/`warning`/`danger`/`gray` | `SeoPositions` (індексація) |
| Порожня таблиця | `emptyStateHeading()` / `emptyStateDescription()` з підказкою, що робити | `SeoPositions` |
| Картка/блок | `Section` (картки одна під одною на 100% ширини) | [forms-cards.md](forms-cards.md) |
| Фільтр за періодом | Бар `HasDateRangeBar` + `date-bar` ([date-filter.md](date-filter.md)) | `ListLeads`, `Payments` |
| Вибір одного значення над таблицею (знімок, менеджер, вакансія…) | Компонент `bar-select` (розділ 4.3) | `SeoPositions` |
| Форми | компоненти Filament (`Select`, `DatePicker`, …) | `LeadResource` |

Заборонено без причини: власна `<table>`, `<button>` замість `Action`/`x-filament::button`, свої стилі вкладок, власні «картки» із inline-стилями, власні вспливаючі вікна замість `Action->modal*`.

## 3. Як будувати сторінку

1. Подивитись схожу готову сторінку (`Reminders`, `ManagerConversion`, `SeoPositions`) і повторити її патерн.
2. Порядок блоків зверху вниз, **однаковий скрізь**: заголовок і кнопки дій у шапці → вкладки (якщо є) → бар періоду / вибору (якщо є) → таблиця або картки.
3. Усе, що залежить від вкладки чи стану, у `table()` робити **замиканнями** (`fn () => ...`): Filament будує таблицю й схему фільтрів один раз на початку запиту, значення, взяте при побудові, застаріває.
4. Інтерфейс лише українською, числа за українським форматом (кома в десяткових).
5. Нову сторінку видно лише `super_admin`, інші ролі — через «Бокова панель» ([access-roles-panels.md](../arch/access-roles-panels.md)); після нового Page/Resource — `shield:generate`.
6. Нова сторінка, що показує дані з API, не робить запитів на кожне відкриття: дані з БД, оновлення — окремою кнопкою/розкладом.

## 4. Реєстр проєктних стандартів вигляду

Кожен стандарт задано в ОДНОМУ місці. Змінити вигляд = змінити там, а не на сторінках.

### 4.1 Вкладки
- Вигляд: **прямокутні вкладки на одній суцільній лінії, активна з синьою смугою** знизу; світла й темна тема.
- Де задано: `resources/views/filament/components/tabs-styles.blade.php` (підключається глобально з `AppServiceProvider`). На сторінках стилів вкладок не писати.
- Використання: лише `<x-filament::tabs>` і `<x-filament::tabs.item :active wire:click>`; лічильник на вкладці — `:badge`.

### 4.2 Фільтр за періодом (дати)
- Один вигляд скрізь: бар над таблицею — «Період» + «З» + «По», завжди видимий, не в панелі фільтрів таблиці.
- Де задано: трейт `HasDateRangeBar` + `resources/views/filament/components/date-bar.blade.php`. Деталі: [date-filter.md](date-filter.md).

### 4.3 Вибір одного значення над таблицею (`bar-select`)
- Вигляд — як у барі дат: **підпис малим сірим текстом над полем, поле висотою 2.5rem, межа 1px, радіус 3px, без тіні**; стоїть у тому самому місці, де бар дат (над таблицею, під вкладками), займає один рядок.
- Де задано: `resources/views/filament/components/bar-select.blade.php`. Підключення: `@include('filament.components.bar-select', ['label' => '…', 'model' => 'властивістьLivewire', 'options' => [значення => підпис]])`. Значення зберігається у публічній властивості сторінки (`wire:model.live`).
- Не використовувати для цього панель фільтрів таблиці (вона займає пів екрана заради одного поля).

### 4.3а Запам'ятовування стану сторінки (`PersistsPageState`)
- Правило: сторінка з вкладками/вибором/галочками **завжди** повертає користувача туди, де він закінчив (вкладка, вибраний знімок, галочки). Механізм — сесія користувача, як у барі дат: трейт `App\Filament\Concerns\PersistsPageState`.
- Як підключити: `use PersistsPageState;` + `persistedState()` (властивість => список допустимих значень або `null`) + `$this->restorePageState()` в кінці `mount()`. Збереження відбувається само після кожного запиту. Недопустиме значення (напр. видалений знімок) ігнорується.
- Сортування таблиці запам'ятовується стандартно: `->persistSortInSession()` у `table()` (системна можливість Filament, без власного коду); так само для нових таблиць.
- Приклади: `SeoPositions` (вкладка, знімок, «Ховати виключені»), `SeoKeyword` (вкладка). Нові сторінки з вкладками робити лише так. Сесія живе стільки, скільки сесія входу; при виході стан скидається.

### 4.3б Залипаюча шапка таблиць (глобально, нічого підключати не треба)
- Шапка КОЖНОЇ таблиці Filament залипає при гортанні автоматично: компонент `sticky-table-header` підключено глобально (`AppServiceProvider` → `STYLES_AFTER`, поруч із `table-header-styles`). На сторінках не додавати ні `@include`, ні обгорток.
- Таблиця вміщується по ширині → нативний `position: sticky` (плавно); ширша за картку → зсув через JS (може трохи смикатись, бо sticky у контейнері з горизонтальною прокруткою неможливий). Таблиці в модальних вікнах не чіпаються.

### 4.4 Інші глобальні стилі та компоненти
Файли в `resources/views/filament/components/`: `table-header-styles` (шапка таблиць), `sticky-table-header`, `simple-pager`, `page-width-styles` (ширина сторінок), `filled-badge-styles` (бейджі), `status-bar`-компоненти (`lead-indicators-bar` та ін.), `page-doc` (довідка сторінки). Загальні правила (колір, радіуси 3px, хлібні крихти): [general-look.md](general-look.md). Форми, картки, статус-бар: [forms-cards.md](forms-cards.md).

## 5. Як додати або змінити стандарт
1. Зробити елемент глобально (Blade-компонент / глобальний стиль), а не на одній сторінці.
2. Описати тут у розділі 4: де задано, як підключати, як виглядає.
3. Прописати в таблиці розділу 2, що брати для цього випадку.
4. Пройтись по сторінках, які мають цей елемент, і привести їх до стандарту.

## 6. Чекліст перед здачею сторінки
- [ ] Немає власної `<table>`, самописних кнопок і вкладок; кастом (якщо є) — з коментарем чому.
- [ ] Вкладки, бар періоду/вибору, кнопки стоять у стандартному порядку (розділ 3.2).
- [ ] Усе, що залежить від вкладки, — замикання.
- [ ] Статуси — бейджі зі стандартними кольорами; порожній стан має підказку.
- [ ] Український текст, формат чисел; нова сторінка прихована для не-адмінів, виконано `shield:generate`.
- [ ] Блок складніший за таблицю має кнопку «Інструкція».
