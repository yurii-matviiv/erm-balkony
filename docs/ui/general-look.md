# Загальний вигляд адмінки (обидві панелі)

> Частина документації ERM. Індекс і навігація: [CLAUDE.md](../../CLAUDE.md). Читай цей файл, лише якщо задача стосується теми вище.

## Загальні правила вигляду (для ВСІХ сторінок, обох панелей)

Задані один раз у `AdminPanelProvider::configureCommon()`, нічого не треба повторювати на сторінках: (1) хлібні крихти вимкнено (`->breadcrumbs(false)`) — раніше "Заявки > List" дублював заголовок сторінки; (2) основний колір (primary) — фірмовий синій `#2874A6` з логотипа (було бурштиновий): заповнені кнопки мають білий текст, колір спокійніший для менеджера. Нові кнопки/бейджі просто використовують `color('primary')`, без своїх жорстких кольорів.

(3) заокруглення карток, секцій, контейнера таблиці й модалок — мінімальне, 3px (глобальний CSS у head-хуку, як і для полів); дефолтне Filament rounded-xl не залишати.

## Меню менеджера = меню старої CRM

Пласке меню без заголовків груп (порожній `group_label` → `NavigationGroup` без назви), порядок як у старій: Замовлення, Графік монтажів, Лід - заявка (бейдж необроблених), Додати заявку, Не прийняті, Оплати, Додати витрату, Модуль З/П. Останні чотири (крім «Модуль З/П», який уже справжній) — порожні сторінки-заглушки `App\Filament\Manager\Pages\*` (базовий клас `PlaceholderPage`; живуть ПОЗА `App\Filament\Pages`, бо адмін-панель авто-знаходить ту папку, а ці сторінки лише для панелі менеджера; реєструються явно в `ManagerPanelProvider`). Налаштування меню/права для ролі "Менеджер" посіяні міграцією `align_manager_sidebar_with_old_crm` (Dashboard вимкнено — його нема в старому меню). Коли робимо справжню сторінку — залишаємо ім'я класу, щоб permission `View:<Клас>` і налаштування сайдбару збереглись. Іконки пунктів сині (`#4aa3df`), текст білий; активний пункт — лише світла підсвітка фону.

## Згортання бокової панелі кліком по "ERM"

`->sidebarCollapsibleOnDesktop()` (згорнутий стан = вузька смужка ТІЛЬКИ з іконками, не повне зникнення — виправлення користувача після першої версії з FullyCollapsible) в `AdminPanelProvider` + render hook `panels::body.end`: клік по логотипу (`.fi-logo`, і в сайдбарі, і в топбарі) перемикає `$store.sidebar` — стандартний перехід логотипа на домашню сторінку свідомо придушено (preventDefault), логотип тепер лише тогл. **За замовчуванням згорнуто**: при першому візиті хук викликає `close()`; далі Filament сам зберігає вибір через Alpine `$persist` (localStorage, переживає перезапуск браузера). **Пастка з ключем localStorage** (реальний баг першої версії — "не запам'ятовує вибір"): `$persist` додає префікс `_x_` ЛИШЕ без `.as()`; Filament викликає `.as('isOpenDesktop')`, тож справжній ключ — просто `isOpenDesktop`. Перевірка "першого візиту" по `_x_isOpenDesktop` завжди була null → меню закривалось на кожному завантаженні. Гості виключені (на логіні є логотип, але немає сайдбару). Стандартні шеврон-кнопки в топбарі також лишаються робочими.

## Домашня сторінка = перший пункт бокового меню

Стандартну Filament-інфопанель замінено власним `App\Filament\Pages\Dashboard`: при відкритті він переадресовує користувача на ПЕРШИЙ пункт бокової панелі його активної ролі (`NavigationResolver::resolveForSidebar()`). Якщо дашборд свідомо стоїть першим у меню ролі — редіректу немає; якщо меню порожнє — дашборд лишається запасним варіантом. У `AdminPanelProvider` сток-Dashboard прибрано з `->pages()`. Міграція `rekey_dashboard_navigation_settings` перекейовує збережені налаштування панелі зі старого FQCN на новий.
