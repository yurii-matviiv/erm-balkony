# Форми, картки, статус-бар

> Частина документації ERM. Індекс і навігація: [CLAUDE.md](../../CLAUDE.md). Читай цей файл, лише якщо задача стосується теми вище.

## Стандарт верху сторінок ліда і замовлення

Найперший блок сторінки (над статус-баром і всім іншим) — смуга з інформацією про запис: «Менеджер», «Створено» (день тижня, дата, година), для замовлення ще «Консультант», посилання на лід і **Тип замовлення** (випадний список справа в тій самій смузі; змінюється одразу). Лід: `lead-status-bar.blade.php`, замовлення: `order-header.blade.php`. Нові сторінки-записи (картка клієнта, постачальника тощо) робити так само: хто відповідальний і коли створено — завжди першим рядком.

## Правила форм і карток (діють ЗАВЖДИ, на всіх сторінках — користувач не повинен нагадувати)

1. **Поля вводу майже прямокутні** (радіус 3px, як у старій CRM) — глобальний CSS у head-hook `AdminPanelProvider`. Нові поля/модалки нічого окремо не налаштовують.
2. **Усередині картки — жодних кнопок, лише текстові дії-посилання з іконкою** (`Action::make()->link()->icon('heroicon-o-pencil-square')`), прикладом — "Змінити адресу" і "Редагувати клієнта" в картці ліда: праворуч у рядку, текст + олівець як одне посилання. Змінюється значення поля → редагування через таку дію (модалка), а не через окрему кнопку-прямокутник.
3. **Справжні кнопки (заливка) — тільки поза карточкою**: внизу сторінки (напр. "Створити замовлення") або у статус-барі над карткою (напр. "Створити заявку на замір").
4. Рядки картки з підписом ліворуч: підпис = 1/3, значення = 2/3, суцільна лінія під кожним рядком (клас `record-card` на Section, `record-row` на кастомних рядках; кастомні рядки верстати inline-стилями grid `1fr 2fr` — Tailwind-класи з нових Blade потребують `npm run build`).
5. Кнопка "Створити замовлення" — ЗЕЛЕНА (success), у верхньому action-барі ліда поруч із "Створити заявку на замір", завжди доступна, поки замовлення не створене (потім замість неї — зелена "Перейти до замовлення №N"). Інструкції внизу сторінки ліда — під окремим заголовком "Інструкції" з відступом.
6. Залиті кольорові кнопки (primary/success/danger/warning/info) — ЗАВЖДИ насичений темніший фон + БІЛИЙ текст і іконка (глобальний CSS у head-hook; Filament за замовчуванням дає світлий фон + темний текст для success/warning/danger — це виправлено). Сірі/контурні кнопки не чіпаємо.

### Нагадування для ліда (old `manager_reminders`)

Таблиця `manager_reminders` (user_id, lead_id, reminder_text, reminder_datetime, reminder_type — матриця важливе/термінове, is_completed, legacy_id), модель `ManagerReminder`, `Lead::reminders()`. На сторінці ліда: оранжева кнопка "Створити нагадування" в action-барі (модалка: текст, дата-час, тип) і під нею таблиця "Нагадування" з редагуванням на місці (текст/дата — по blur/change, чекбокс "виконано"). `ManagerRemindersSyncMapper` переносить старі (після Users+Leads); правки в новій системі при повторній синхронізації НЕ перезаписуються (оновлюються лише user_id/lead_id). Не зроблено: сторінка "Нагадування" в меню менеджера (/manager/reminders), сповіщення/попап про сьогоднішні нагадування. Статус-бар ліда: короткі назви в один рядок (Новий, Контакт, Замір, Заміряно, КП, Узгодження, Замовлення), в окремій сірій панелі, відділено від кнопок. Етапи — НЕ зі старої CRM, питання про заміну на старі статуси відкрите.

## Єдиний статус-бар (`<x-status-bar>`)

Усі статус-бари (лід, замовлення, далі інші) — ОДИН компонент `resources/views/components/status-bar.blade.php`, стилі `.sb*` у head-хуку `AdminPanelProvider`. Правила: завжди ВГОРУ сторінки; кожен етап — прямокутник (3px), під кожним лінія: пройдені — синя, поточний — яскрава помаранчева з підсвіткою, майбутні — сіра; скасоване/відхилене — окремий червоний індикатор (`extra`) і приглушений прогрес. Props: `steps` [key => label/date], `current`, `click` (Livewire-метод `setStage`), `extra`. Нові статус-бари робити ТІЛЬКИ через цей компонент. Замовлення: дати під етапами (measurement/readiness/montage/success), заголовок "Замовлення №" прибрано з картки (є в заголовку сторінки), бейдж етапу прибрано (дублював бар).

## Картки замовлення: "input-group" як у старій CRM (`ig-card`)

У старій CRM кожне поле — Bootstrap `input-group`: підпис («Замір») і значення — ОДИН суцільний блок, підпис у сірому боксі зліва. Тепер так само в нових картках: `Section->extraAttributes(['class' => 'ig-card'])->inlineLabel()`; CSS `.ig-card` у head-хуку `AdminPanelProvider` робить ліву/праву частини рівно 50/50 (grid 1fr 1fr), для ВСІХ полів однаково (поля, TextEntry, toggle). Довгі пояснення — через `hintIcon(... tooltip:)`, а НЕ `helperText` (він ламає рівну висоту). Рядок-посилання без підпису — `extraAttributes(['class' => 'ig-plain'])`. Застосовано до EditOrder; наступні картки (лід тощо) переводити на цей же клас.

**Уточнення `ig-card` (2026-11-14):** підпис має ФІКСОВАНУ однакову ширину (11rem), решта рядка — поле (50/50 не підходило: у вузькому вікні дати обрізались). Кількість колонок залежить від ширини КАРТКИ, а не вікна: `Grid::make(['default'=>1,'@3xl'=>2,'@6xl'=>3])->gridContainer()` (container queries) — так само робити в усіх `ig-card`. Дати — `->displayFormat('d.m.Y')` + `->suffixIcon('heroicon-o-calendar-days')`.
